## 3. 已知未验证边界（不是缺陷，是"没证据"）

| 项 | 状态 | 计划 |
| --- | --- | --- |
| **Python 3.8 兼容性** | ⚠️ 静态检查通过（AST 扫描 `list[int]` / `X \| Y`），**未在真实 3.8 上运行** | M5 用干净环境实测；若无法获得 3.8 环境，在 README 里明确写"实测于 3.10" |
| **真机 VX（`.rvdata`）/ 纯 XP（`.rxdata`）样本** | ⚠️ **仍空白**（M2a 已用合成样本覆盖 `standard=True` 的逻辑路径，见 ADR-013） | 合成样本覆盖不到**汉化/破解变体**；有条件时补真机样本 |
| **非 Windows 平台** | ⚠️ `winreg` 已改为函数内 import（B-26 已修），模块可正常导入；但**未在 Linux/macOS 上实测** | M5 若有机会在 WSL/Linux 跑一次 `python app.py --check` 与 `tests/run_all.py` |
| **大型游戏全量扫描性能** | ⚠️ M0 实测 MZ 样本扫描 67,756 条文本，原工具可完成但耗时未量化 | M3a 接线时补一条大样本扫描的耗时记录；需求 §9 要求后台任务 + 进度反馈（已就绪） |
| **加密 JSON 包装的变体** | ⚠️ 只验证了 `{"uid","bid","data"}` 一种形状 | M2b/M3a 收集更多变体并登记 |
| **MTool / 汉化版运行时变体** | ⚠️ 已知存在（`_fixnum` 变体、浮点尾、自定义 `U`），但**没有系统化样本矩阵** | 在 `docs/MODULES.md` 与本案逐条记录已知变体与容错点 |

## 5. 想法池（**当前的工作清单** —— 加功能从这里挑）

按"价值 / 成本"排序。每条都写清了**落点**与**验收判据**，
这样可以直接按 `AGENTS.md` §5 的"变更三连"（代码 + 测试 + 足迹）开工。

### 5.1 性价比高的（建议优先）

| # | 功能 | 价值 | 落点 | 验收判据 |
| --- | --- | --- | --- | --- |
| **F-01** | **汉化版差异报告**：生成后列出"改了哪些文件、各多少条、字体动过什么" | 用户安全感的直接来源；现在只有一句"写回 N 条"，出问题时无法自证 | `core/safety/builder.py` 的 `build()` 返回值 + `ui/web/pages/translate.js` 的结果卡 | 构建结果里有一张按文件的明细表；有断言核对条数与实际改动一致 |
| **F-02** | **存档改前改后 diff**：保存前展示"哪些字段从什么变成什么" | 让"只改目标字段"可自证；改档最怕改坏别的 | `features/cheats/routes.py` + 页面新增对比面板 | 保存前能看到结构化 diff；有断言：未改动的字段不出现在 diff 里 |
| **F-03** | **翻译记忆库跨游戏共享** | 同一系列/同一引擎的游戏大量重复文本，现在每个游戏都要重翻 | 新增 `core/tmdb.py`（SQLite，标准库自带）+ `translators.translate_entries` 接入 | 第二个游戏能命中第一个游戏的记忆；有断言命中率与一致性 |
| **F-04** | **批量处理多个存档** | 多套存档（本体 + 自动存档）现在要一个个改 | `features/cheats/routes.py` 加"对所有存档应用同一改动" + 任务化 | 一次操作改完所有存档且各自备份；有断言 |
| **F-05** | **引擎识别结果可手工覆盖** | 结构特殊的汉化/破解版识别错时，现在完全没法用 | `features/*/routes.py` 加"手动指定资源根/布局/编码" + 会话内持久化 | 手工覆盖后扫描与写回都按覆盖值走；有断言 |

### 5.2 明确想做但成本更高

| # | 功能 | 价值 | 主要成本 |

### 5.3 已放弃/不改

见 §4「明确不做」。

### 5.4 建议的开工顺序

1. **F-01 差异报告** —— 成本最低、用户感知最强，且能立刻用上现在的构建结果结构。
2. **F-02 存档 diff** —— 与 F-01 同一套思路（"让改动可见"），可复用组件。
3. **F-05 手工覆盖识别** —— 解锁"识别错了就没救"这一类游戏，风险低。
4. **F-03 翻译记忆库** —— 价值最高但工作量最大，放后面。
