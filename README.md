# RPG Maker 全能工具

> **English**: An all-in-one toolkit for RPG Maker games (**MV / MZ / VX Ace / VX / XP**) —
> extract & machine-translate all in-game text and build a localized copy, and edit save
> files / game data (gold, items, actors, switches). Pure **Python standard library**,
> **zero dependencies**, no build step. UI is in Chinese. Licensed under MIT.

把「翻译」和「改档」两件事合并进同一个工具：

| 功能 | 做什么 |
| --- | --- |
| **文本翻译** | 扫描游戏内全部文本 → 批量机翻 → 生成汉化版（可选注入中文字体）→ 一键还原 |
| **存档修改** | 改金币 / 步数 / 道具 / 角色属性 / 开关变量，也能改游戏数据表（价格、攻击力…） |
| **环境自检** | 显示识别到的引擎、目录、功能装配情况与能力边界（排查"为什么我这里不行"） |

**引擎支持**：RPG Maker **MV / MZ / VX Ace / VX / XP** 可读可写；**2000/2003 只识别、不修改**。
汉化版 / 破解版 / MTool 修改版游戏也做了容错（加密 JSON 包装、非标准 Marshal、多流存档、额外字段）。

```
Python 3.8+   ·   零第三方依赖   ·   1090 个测试   ·   无构建步骤   ·   Windows 实测通过
```

## 一、怎么启动

### 方式 1：双击（推荐）

双击 **`启动.bat`**。它会自己找 Python、做一次自检、启动服务并打开浏览器。

### 方式 2：命令行

```powershell
python app.py                 # 启动并自动打开浏览器（默认 127.0.0.1:8765）
python app.py --port 8765     # 指定端口（填 0 取随机空闲端口）
python app.py --host 0.0.0.0  # 绑定其它网卡（默认只绑本机）
python app.py --no-browser    # 不自动打开浏览器
python app.py --dir "D:\games\我的游戏"   # 启动后直接载入这个游戏
python app.py --check         # 只自检并退出（退出码 0 = 通过）
python app.py --check --json  # 机器可读的自检报告
python app.py --no-reclaim    # 不回收占用端口的旧实例
```

浏览器会打开 `http://127.0.0.1:8765`（端口被占用时会自动换）。
**关掉窗口（或按 Ctrl+C）即退出。**

### 环境要求

| 项 | 要求 |
| --- | --- |
| Python | **3.8 或更高**（3.10 实测通过；3.8 为静态语法兼容，未在真实 3.8 上跑过） |
| 第三方包 | **一个都不需要** —— 整个工程只用标准库，不需要 `pip install` |
| 系统 | Windows 实测通过；macOS / Linux 未验证（代码里只有"在文件管理器中打开目录"和"原生文件对话框"两处平台分支） |
| Node（可选） | 只用于前端冒烟测试；**没装 Node 时相关测试自动跳过**，不影响使用 |

## 二、文本翻译怎么用

1. **选游戏目录** —— 填或点「浏览…」，指到含 `www` / `data` / `Data` 的那一层，
   点「打开并识别」。工具会显示识别到的引擎与数据目录。
2. **扫描文本** —— 勾选要提取的内容（注释 / 备注 / 事件名 / 动画名），点「扫描文本」。
   几万条文本在后台跑，有进度条，**可以随时取消**。
3. **看列表、改译文** —— 支持搜索、按类别（对话 / 名称 / 描述…）与状态筛选。
   行内改译文，回车即存；不想翻的条目点「跳过」。
   **进度会自动保存**，关掉工具再打开同一游戏可以接着做。
4. **设置翻译引擎** —— 四种可选，填完点「接口自检」确认能通，再点「开始翻译」：

   | 引擎 | 说明 |
   | --- | --- |
   | **Google 翻译** | 免费，不需要密钥 |
   | **OpenAI 兼容接口** | 填 OpenAI / DeepSeek / Kimi / Qwen 等的地址与密钥 |
   | **本地 Ollama** | 默认 `http://localhost:11434/v1`，**完全离线** |
   | **DeepL** | 需要 DeepL API Key |

5. **生成汉化版** —— 两种方式：

   * **写副本（默认、推荐）**：复制到新目录（默认 `<游戏名>_汉化`），**原游戏一个字节都不动**
   * **覆盖原游戏**：直接改原目录，**会先自动备份**，并把备份路径显示在界面上

   可选注入中文字体（MV/MZ 改写 `core.js`；VX Ace/XP 装进系统字体库并注入脚本）。
6. **还原** —— 「刷新备份列表」里可一键还原任何一次备份。
   **还原之前还会自动再备份一次当前状态** —— 所以"还原错了"也能再还原回来。

## 三、存档修改怎么用

1. **读取游戏数据** —— 选游戏目录，点「读取游戏数据」。
2. **选存档** —— 列表里选一个点「载入」。
   如果发现**多个含存档的目录**（有些游戏有自动存档），界面会提醒你确认改的是哪一个。
   标准目录里找不到存档时，还可以按扩展名**全盘搜索**。
3. **改数值** —— 改动先放在**内存**里，界面顶部会显示「有未保存的改动」：

   | 能改什么 | 说明 |
   | --- | --- |
   | **金币 / 步数 / 道具** | 列出**整张数据表**（没持有的显示 0，可直接添加）；带**游戏内图标**、搜索与「只看已持有」筛选 |
   | **角色** | 等级 / 经验 / HP / MP / 属性加成 / 技能列表 |
   | **开关 / 变量** | 开关勾选，变量填数字，分页 + 按编号跳转 |
   | **游戏数据表** | 改价格 / 攻击力 / 初始等级等（这一项**作用于所有存档**） |

   > **游戏内图标**：道具 / 武器 / 防具列表可在名称前显示游戏里的图标。
   > 有些道具的名字是乱码、纯数字、甚至没有名字，图标是唯一能分辨它们的线索。
   > 图标直接读游戏的 `IconSet` 图集（MV/MZ 的加密资源 `.rpgmvp` / `.png_` 会自动解密），
   > 不需要额外下载任何东西。图集解不开时会**置灰开关并说明原因**，不会画出错位的图。

4. **保存存档** —— 点「保存存档」并确认。写回前自动备份，保存后界面显示**本次备份位置**。
   不想改了就点「放弃改动并重新载入」。
5. **还原** —— 和翻译一样，备份列表可一键还原，还原前再备份一次。

> **队伍成员只读**：这是原工具的既有行为（没有写回路径），本工程保持一致。

## 四、安全约定（硬约束）

这些不是建议，而是代码里被测试强制的约定：

| 约定 | 说明 |
| --- | --- |
| **默认零破坏** | 翻译默认只写副本；改存档默认只改内存，点保存才落盘 |
| **写前必备份** | 任何覆盖操作前，先把将被修改的文件复制到游戏目录下的「汉化备份_*」 |
| **备份可还原** | 备份列表在界面上可点；还原前还会为当前状态再备份一次 |
| **覆盖要确认** | 覆盖原游戏 / 写回原存档 / 写回数据表 / 还原，都要先弹二次确认（且不记忆） |
| **原子写入** | 写文件用"临时文件 + 原子替换"，中途失败/断电时原文件一个字节都不变 |
| **未改内容原样保留** | 没动过的字段按**字节**保留（有 300 个真实存档样本的零漂移断言） |
| **不碰游戏目录以外的东西** | 读存档的路径必须落在本游戏的存档目录内；服务只绑本机并校验 Host/Origin |

## 五、常见问题

**Q：双击 `启动.bat` 没反应 / 闪一下就没了？**
A：说明没找到 Python 或自检没过。在命令行里跑一次，错误信息会留住：

```powershell
python app.py --check
```

**Q：提示端口被占用？**
A：`启动.bat --port 0` 会用随机空闲端口；或关掉占用该端口的程序。
若占用者是本工具的**旧实例**，`app.py` 会**主动回收**它（回收前先校验它的 `/api/health`，
确认是自己人才动手）；不想回收就加 `--no-reclaim`。

**Q：翻译了一大堆但游戏里没变？**
A：检查是不是选了「写副本」—— 那样汉化版在**新目录**里，原游戏不会变。
若确实要改原游戏，选「覆盖原游戏」，它会先备份。

**Q：改完存档游戏读不出来？**
A：在「备份列表」里点该次备份的「还原」。还原前工具还会为当前状态再备份一次。

**Q：道具列表里有些行没有图标，是不是读失败了？**
A：如果那一行显示**虚线空框**，说明游戏数据里这条的图标编号就是 `0`（游戏里也不画图标）；
把鼠标停在框上会写明原因。如果开关是**灰的**，那行说明文字会告诉你为什么
（找不到图集 / 图集解不开 / 图集尺寸不认识）。

**Q：列表里为什么有一些 `#编号`？**
A：那是数据表里有 id、但既没名字也没图标的**空槽位**，默认会被隐藏并告诉你有多少个。
只有"有名字"或"有图标"或"你正持有"的条目才会列出来。

**Q：支持哪些游戏？**
A：MV / MZ / VX Ace / VX / XP 可读可写；2000/2003 只识别不修改。
各类变体（汉化版 / 破解版 / MTool 修改版）的容错范围有明确记录，
已知边界见 [`docs/OPEN-QUESTIONS.md`](docs/OPEN-QUESTIONS.md) 附录。

**Q：会不会把我游戏改坏？**
A：默认只写副本；覆盖前自动备份；写盘走原子替换；全部都要求二次确认。
工程里 1090 个测试中相当一部分就是钉这些性质的（包括"接口说成功、文件却没变"这类缺陷的回归）。

## 六、隐私

* **翻译出网请求只包含剥离控制码后的纯文本** —— 不含文件名、路径、游戏目录。
* 在线翻译路径**默认不参与测试**（避免因对方服务波动而红灯）；连通性用界面上的
  「接口自检」由你自己验证。
* API Key 只存在本地 `config.json`，**已在 `.gitignore` 里**，不会进仓库。
* 服务只绑 `127.0.0.1`，并校验 `Host` / `Origin`，防止其它本地网页越权调用。

## 七、开发者入口

> 想改代码 / 接手这个工程，先读 **[`AGENTS.md`](AGENTS.md)**（开工指令）
> 与 **[`docs/STATE.md`](docs/STATE.md)**（当前状态快照）。

```powershell
python tests/run_all.py              # 全部测试（退出码 0 = 通过）
python tests/run_all.py --list       # 看各层用例数
python tests/run_all.py --suite unit # 只跑某一层
python tools/check_footprint.py      # 足迹校验（47 个源文件 / 3 个功能）
python tools/gen_footprint.py        # 源码变动后刷新 docs/footprint.json
python tools/check_secrets.py        # 发布前：扫 git 历史里有没有泄漏 API Key

# 真实游戏样本（不入库；用环境变量指向本机游戏库）
$env:TUDOU_RPGTOOL_SAMPLES = 'D:\gamess'
python tests/run_all.py
```

### 配置

复制 **`config.example.json`** 为 `config.json` 再填自己的值。**`config.json` 已在
`.gitignore` 里 —— 不要提交它**（里面有你的 API Key）。什么都不填也能跑：
Google 翻译不需要密钥，本地 Ollama 通常也不需要。

> ⚠ 只加 `.gitignore` **挡不住已经提交过的东西**：key 一旦进过提交，就永久留在
> git 对象里，`git push` 会把整个历史一起推上去（本地 `git status` 干干净净也没用）。
> 发布前跑一次 `python tools/check_secrets.py` —— 它扫的是**所有提交里的所有 blob**，
> 并且会把本机 `config.json` 里的真实 key 拿去历史里精确匹配。

| 测试层 | 用例数 | 说明 |
| --- | --- | --- |
| `unit/` | 463 | 纯单元，零外部依赖 |
| `compat/` | 98 | 原两个工具断言的可迁移版本 + 缺陷回归 + 合成 VX/XP 样本 |
| `features/` | 384 | 三个功能模块的自有测试 |
| `integration/` | 145 | 端到端链路、零第三方依赖扫描、3.8 语法扫描、页面契约、**真的用 DOM 探针跑一遍前端** |

**加一个新功能只需要三步**（契约见 [`docs/FEATURES.md`](docs/FEATURES.md)）：

1. 建 `features/<名字>/`：`__init__.py` + `manifest.py`（含 `MANIFEST` 与 `register(ctx)`）
2. 建 `ui/web/pages/<页面id>.js`（导出 `render(host, ctx)`）
3. 建 `tests/features/<名字>/test_manifest.py`

导航会自动出现 —— **不需要改 `app.py` / `ui/server.py` / `index.html`**。
（`selfcheck` 这个功能就是这么加进去的，外壳一行没动。）

## 八、目录结构

```text
├─ 启动.bat / run.py       # 双击启动入口（批处理只做转发，逻辑在 run.py）
├─ app.py                  # 唯一入口：装配 core/ui/features 并启动服务
├─ core/                   # 与界面无关的纯逻辑（不得 import ui / features）
│  ├─ engines.py           #   引擎识别 + 数据/存档目录发现（唯一实现）
│  ├─ iconutil.py          #   游戏内图标图集：定位 / 解密 / 切片几何
│  ├─ recent.py            #   「最近打开的游戏」
│  ├─ marshal/             #   Ruby Marshal（字节级保真）
│  ├─ formats/             #   MV/MZ 与 RGSS 的数据、存档读写
│  └─ safety/              #   原子写 / 备份还原 / 生成汉化版编排 / 字体
├─ features/               # 一个目录 = 一个可插拔功能
│  ├─ translate/           #   文本翻译
│  ├─ cheats/              #   存档修改
│  └─ selfcheck/           #   环境自检
├─ ui/                     # 界面：HTTP 服务 + 无构建的单页前端（原生 ES 模块）
├─ tests/                  # unit / compat / features / integration / local
├─ tools/                  # 足迹校验与生成、前端冒烟探针
├─ docs/                   # 状态、架构、决策、足迹、UI 规格（AGENTS.md 指明阅读顺序）
└─ runtime/                # 运行时数据（会话、最近打开；不入库）
```

**依赖方向单向**：`features` → `core`，`ui` → `core` + `features` 的公开接口；
`core` 不得 import `ui` 或 `features`（由足迹校验静态强制）。
